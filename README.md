# Vorfahrt

Vorfahrt is a simple, queueing SMTP server written in Go. It is designed to run in a Docker environment, particularly alongside Traefik. It provides a minimal Web UI for managing sender accounts and inspecting the outbound queue.

## Features

- **SMTP Server**: Accepts incoming emails and stores them in a local SQLite database.
- **Queueing & Delivery**: A background worker automatically attempts to deliver queued emails to their destination MX servers (with up to 5 retries). Expired queue items are automatically purged after 24h (configurable via `QUEUE_RETENTION`).
- **Traefik ACME Integration**: Automatically reads and watches Traefik's `acme.json` to secure the SMTP connection (STARTTLS) and validate allowed `MAIL FROM` sender domains. Re-reads automatically on Web UI visits and file modifications.
- **Domain-Tethered Accounts**: Sender accounts are strictly tethered to a single configured domain, preventing unauthorized spoofing across domains.
- **Autogenerated Credentials**: Account passwords are automatically generated secure strings that cannot be altered.
- **DKIM Signing**: Automatically generates a DKIM key and signs all outgoing messages to improve deliverability.
- **Web UI**: A simple interface to create and manage domain-tethered sender credentials, inspect the email queue, verify server Forward-Confirmed Reverse DNS (FCrDNS / PTR), and check per-domain authentication status (SPF, DKIM, DMARC).

## Example `compose.yml`

Below is a complete example showing how **Traefik**, **Vorfahrt**, and your **application(s)** can be set up together:

- **Traefik** terminates HTTPS, acquires Let's Encrypt certificates, and stores them in `acme.json`.
- **Vorfahrt** mounts `acme.json` (read-only) for STARTTLS and sender domain validation, serves its Web UI behind Traefik, and acts as an authenticated SMTP relay.
- **Your App** connects to Vorfahrt over the internal Docker network using sender credentials generated in Vorfahrt's Web UI.

```yaml
services:
  traefik:
    image: traefik:v3.0
    command:
      - "--providers.docker=true"
      - "--providers.docker.exposedbydefault=false"
      - "--entrypoints.web.address=:80"
      - "--entrypoints.websecure.address=:443"
      - "--certificatesresolvers.myresolver.acme.tlschallenge=true"
      - "--certificatesresolvers.myresolver.acme.email=admin@example.com"
      - "--certificatesresolvers.myresolver.acme.storage=/letsencrypt/acme.json"
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - "/var/run/docker.sock:/var/run/docker.sock:ro"
      - "./letsencrypt:/letsencrypt"
    networks:
      - web
    restart: unless-stopped

  vorfahrt:
    image: ghcr.io/saibotd/vorfahrt:latest # or build: .
    environment:
      # Primary server hostname for SMTP EHLO/HELO and rDNS (PTR) validation
      - SMTP_DOMAIN=mail.example.com
      # SMTP listen address inside the container
      - SMTP_ADDR=:25
      # Path to mounted acme.json for TLS certs and sender domain validation
      - ACME_FILE=/data/acme.json
      # Storage directory for SQLite database (data.db) and keys
      - DATA_DIR=/data
      - DKIM_KEY_FILE=/data/dkim.key
      - DKIM_SELECTOR=mail
      - QUEUE_RETENTION=24h
      # Web UI credentials
      - WEB_ADDR=:8080
      - WEB_USERNAME=admin
      - WEB_PASSWORD=replace-with-a-secure-password
    volumes:
      # Read-only mount of Traefik's acme.json for TLS certs & domain validation
      - "./letsencrypt/acme.json:/data/acme.json:ro"
      # Persistent storage for SQLite DB and generated DKIM key
      - "./vorfahrt-data:/data"
    # ports:
    #   - "25:25" # Optional: only expose to the host if accepting SMTP from outside Docker
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.vorfahrt.rule=Host(`mail.example.com`)"
      - "traefik.http.routers.vorfahrt.entrypoints=websecure"
      - "traefik.http.routers.vorfahrt.tls.certresolver=myresolver"
      - "traefik.http.services.vorfahrt.loadbalancer.server.port=8080"
    networks:
      - web
    restart: unless-stopped

  myapp:
    image: my-app:latest
    environment:
      # Route outgoing email through Vorfahrt over the shared Docker network
      - SMTP_HOST=vorfahrt
      - SMTP_PORT=25
      - SMTP_USER=myapp
      - SMTP_PASSWORD=generated-in-vorfahrt-ui
      - SMTP_FROM=hello@example.com
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.myapp.rule=Host(`example.com`)"
      - "traefik.http.routers.myapp.entrypoints=websecure"
      - "traefik.http.routers.myapp.tls.certresolver=myresolver"
      - "traefik.http.services.myapp.loadbalancer.server.port=3000"
    networks:
      - web
    depends_on:
      - vorfahrt
    restart: unless-stopped

networks:
  web:
    driver: bridge
```

## Quick Start

1. Configure your `compose.yml` (see example above), ensuring Traefik stores certificates in an `acme.json` file mounted into Vorfahrt.
2. Start the services:
   ```bash
   docker compose up -d
   ```
3. Access the Web UI at `https://mail.example.com` (or `http://localhost:8080` if accessing locally).
4. Check **Server Identity & Connectivity** in the UI to confirm PTR (FCrDNS) and outbound port 25 status.
5. Create sender credentials tethered to your domain (e.g., `example.com`) and configure your app to use them.

## Environment Variables

| Variable | Default | Description |
|---|---|---|
| `ACME_FILE` | | Path to Traefik's `acme.json`. Used for TLS certs and sender domain validation. |
| `DATA_DIR` | `data` | Directory where the SQLite database and DKIM key are stored. |
| `DKIM_KEY_FILE` | `data/dkim.key` | Path to the RSA private key used for DKIM signing. Auto-generated if missing. |
| `DKIM_SELECTOR` | `mail` | The DKIM selector used in DNS records. |
| `QUEUE_RETENTION` | `24h` | Duration after which messages in the queue are deleted (e.g. `24h`, `48h`, `7d`). Set to `0` to disable. |
| `WEB_ADDR` | `:8080` | Port for the Web UI and API. |
| `WEB_USERNAME` | `admin` | Username for basic auth on the Web UI. |
| `WEB_PASSWORD` | | Password for basic auth on the Web UI. If empty, auth is disabled. |
| `SMTP_ADDR` | `:25` | Port for the SMTP server. |
| `SMTP_DOMAIN` | `localhost` | The EHLO domain announced by the server. |
| `SMTP_IMPLICIT_TLS`| `false` | If `true`, requires TLS from the first byte (usually for port 465). If `false`, uses STARTTLS. |

## DNS & Server Identity Configuration

For multi-domain mail delivery, recipient servers (Gmail, Microsoft, etc.) verify identity across two levels:

1. **Server Identity (rDNS / FCrDNS) & Connectivity**:
   - **Outbound Port 25**: Verifies that your host/firewall allows outbound TCP traffic on port 25. Most cloud VPS providers (Hetzner, AWS, DigitalOcean, Linode, etc.) block outbound port 25 by default to prevent spam; if blocked, an action notice is shown to request unblocking.
   - **FCrDNS**: Your server IP requires **one** PTR record pointing to your primary canonical hostname (configured via `SMTP_DOMAIN`, e.g. `mail.example.com`).
   - The Vorfahrt Web UI automatically checks this under **Server Identity & Connectivity** and warns if your VPS provider's PTR record mismatches your `SMTP_DOMAIN` or if port 25 is blocked.
   
2. **Per-Domain Authentication (SPF, DKIM, DMARC)**:
   - For every sender domain configured in `acme.json`, the Web UI checks:
     - **SPF**: Authorizes your primary mail server to send mail for the domain (`v=spf1 a:<SMTP_DOMAIN> mx ~all`).
     - **DKIM**: Verifies `v=DKIM1` on `mail._domainkey.<domain>`.
     - **DMARC**: Verifies `v=DMARC1` on `_dmarc.<domain>`.

## Local Development

To run the server locally for testing (without root privileges):

```bash
# Create a dummy acme.json or use a test file
SMTP_ADDR=":2525" WEB_ADDR=":8080" ACME_FILE="_testdata/acme.json" go run .
```

You can test sending an email through it using `swaks`:
```bash
swaks --to recipient@example.com --from sender@your-domain.com --server localhost --port 2525 --auth-user sender --auth-password <autogenerated-password>
```
*(Ensure the sender account is created in the UI and tethered to `your-domain.com` first!)*
